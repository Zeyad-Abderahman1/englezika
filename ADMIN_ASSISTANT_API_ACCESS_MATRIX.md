## 2. API Security Architecture Summary

1. **Authentication Token Storage:** Cryptographically random 32-byte tokens (`crypto.getRandomValues(32)`), stored only as SHA-256 hashes in `staff_sessions`.
2. **Permission Guard:** `apiStaff(request, requiredPermission)`:
   - Verifies session token hash against active `staff_users` record (`active = 1`).
   - If user role is `teacher`, all permission checks automatically evaluate to `true`.
   - If user role is `assistant`, the user's parsed JSON permissions must explicitly contain `requiredPermission`.
3. **Same-Origin Protection:** All mutating endpoints (`POST`, `PATCH`, `DELETE`) call `requireSameOrigin(request)` to prevent cross-site request forgery.
4. **Rate Limiting & Lockout:** Login endpoint is protected by IP rate limiting (5 attempts/min) and database-backed lockout (5 failures = 15 minutes lock).
5. **No Exposure of Sensitive Files:** Student birth certificate endpoint (`/api/admin/students/[email]/birth-certificate`) authenticates caller with `view_students`, streams private storage objects directly, and sets strict `private, no-store` caching headers.
